# GitKay 0.17.0

GitKay moves to Axial 0.13.0 and gives the runtime the work it should own: the app no longer starts its own
runtime, reads the machine or writes files from inside `update`.

## Highlights

- The commit list has no column header row. The columns are still resizable: each column boundary is a drag handle
  over the whole list, so a column is sized by dragging its edge anywhere down the history.
- The diff pane always shows the file the files pane has selected. Picking a commit (or stepping through them with the
  arrow keys) puts the selected file's header at the top of the diff and keeps it there while that file's rows load,
  instead of leaving the viewport in whichever file the previous rows happened to anchor.

## Under the hood

- Axial 0.13.0: `ElmishRuntime.startLayer` starts the app's runtime in the host, and `update` is pure — timings arrive in
  messages, the launch directory is read once by the host, and the diagnostics registry is fed by the host.
- Search progress streams through `Cmd.OfFlowStream.latest` and the working-tree watch is `Files.watch` debounced by
  `FlowStream.debounce`, replacing the hand-rolled debounce and file watcher. The watcher reports a quiet period after the
  last change, quietly filters git internals, and is restarted by a new subscription id after a failure.
- External launches (browser, file manager, VS Code, GitKay itself) and the git reads and stores the UI triggers run as
  Core flows through `Process.launch` / `Process.shellOpen`, so a program that will not start is a typed `ProcessError`
  instead of a caught exception.
- Settings, UI state and persistence read and write through `Axial.FileSystem`; the synchronous store calls and the
  coalescing writer are the only host-side file access left.
- Axial Guardrails now analyses every F# project, with the test role for the test projects, and the release gate is the
  full check (`dotnet axial check --full --configuration Release`).
