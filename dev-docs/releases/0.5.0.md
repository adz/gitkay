# GitKay 0.5.0

## Search from the keyboard

- **`/` and `?` open a search prompt in the status bar**, like vim: it searches as you type, Enter returns to the pane
  and keeps the search for `n`/`N`, and Esc puts the find text, focus and scroll position back. An empty `/` repeats
  the last search, Up/Down recall earlier ones, and the prompt shows its keys while you type.
- **Patterns work like vim:** regex with smartcase (all lowercase ignores case), `/i` or `\c` to ignore case, `/c` or
  `\C` to match it, `\V` for literal text from that point on (`\v` back to regex), `\<` `\>` for word boundaries.
  Alt+R and Alt+C toggle regex and case.
- In the diff, the prompt drives find-in-diff, so the find box shows what `n`/`N` step through. In the commit list it
  matches loaded commits' subject, author and hash, and underlines the matches.
- `Ctrl+F` still opens the find box, where Enter keeps stepping. **`F1` now opens the shortcut sheet** (`?` still does
  outside the panes).

## Panes and screen movement

- **`Ctrl+W` then `h`/`j`/`k`/`l`** (or arrows, or with Ctrl held) moves between panes; `w`/`W` cycles and `p` goes back.
  `Ctrl+W o` maximises the focused pane (again to restore), `_` and `|` maximise its height or width, and `=` restores
  the layout. The saved layout stays the normal one while a pane is maximised.
- **`H`/`M`/`L`** focus the top, middle or bottom row on screen (`3H`: third from the top), **`Ctrl+E`/`Ctrl+Y`** scroll
  one row without moving the focus, and **`PageUp`/`PageDown`** move a screen, in the commit list and the diff.

## Fixes

- With nothing focused in the commit list, `/` and `{count}G` landed one row early.
- `[c` from a hunk's first line didn't move.
- `{count}G` in unified view could land on a removed line with that old line number instead of the new line.
- The changed-files list's path highlight ignored the search's regex setting, and highlights in the diff appeared
  only after a second delay.
- The hints shown while holding Ctrl name the full shortcut (`Ctrl+3 files · Ctrl+P go to file`).

## Under the hood

- Settings, UI state, search query editing, diff layout, navigation and selection, and commit formatting moved from
  the C# views into tested F# modules, with general-purpose pieces (text queries, match stepping, recent lists, fuzzy
  ranking, back/forward history, path trees) in a new `GitKay.Kit` library. About 700 lines of unused diff search
  state were removed.
- The command line is read by pure option readers with typed errors, and settings files decode to a result instead of
  failing silently.
