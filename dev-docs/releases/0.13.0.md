# GitKay 0.13.0

## Highlights

- The commit window now shares the history window's changed-file rows, file tree and all-files views, command palette, pane navigation and shortcuts. Stage or unstage a file, hunk or selected lines, then commit without losing your place in history.
- Staging a hunk or selected lines can be reversed with `u`, including repeated staging actions. Discard still asks first and offers Ctrl+Z to restore the backed-up working file.
- Folder browse and compare windows refresh in place, preserving the selected file, focus and scroll position. Markdown preview changes also keep the text you were reading anchored on screen.
- Branch actions live on local branch badges. Push refuses to write a branch onto a differently named upstream; pull reports its configured behavior; ordinary fetch respects Git's pruning settings, with an explicit fetch-and-prune action alongside it.

## Safer repository actions

- Creating a branch or tag asks for its name. Soft and hard reset are grouped under **Advanced** and require confirmation; the hard reset warning explains that discard undo cannot reverse it.
- Commit-and-push applies its push intent only to the successful commit attempt that requested it.
- Staged-file discard runs its unstage and discard steps in order, including newly added files.

## Interface and fixes

- Changed-file rows use the same layout across history, commit and folder windows. Preview and whitespace controls state what they show instead of relying on tint alone.
- Shared shortcuts now come from one key map, and the UI tests capture real rendered pixels to catch unreadable controls and layout shifts.
- Fixed line selection in side-by-side diffs, formatted preview context, and several cases where late content or a refreshed file list moved what was on screen.
