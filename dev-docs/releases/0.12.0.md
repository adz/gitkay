# GitKay 0.12.0

## Highlights

- GitKay now runs without a repository: `gitkay diff <a> <b>` compares two folders and `gitkay browse <dir>` reads one. Starting GitKay in a folder that is not a repository browses it.
- Folder windows carry the same file list, diff surface, previews, syntax highlighting, find, go-to-file and settings the repository windows use, with the two folders shown where a repository window shows its commits.
- Preview covers more than Markdown: JSON and XML are reformatted deterministically and re-diffed, so a change shows as a change rather than a re-indent, and image files show themselves with their format, dimensions and size.
- Image previews zoom with Ctrl+wheel or +/-/0 and pan by dragging, without disturbing text selection anywhere else.
- Rendered Markdown gained a changes-only toggle in the file header, and a command to forget the per-file preview choices that outrank the default.
- The window's chrome — toolbar, column headers and pane header bars — no longer shares the content's background; it is configurable as a surface, transparent or a tint, with a wider colour list shared with pane borders and effects.
- Changed-file rows show exact `+N −M` counts, with the five-block graph dropping out when a long path needs the room.
- Clicking a commit hash copies it, and the commit context menu offers copy hash and copy subject.

## Fixes

- Toggling a Markdown preview no longer loses the scroll position: the anchor now stays within the file it belongs to instead of matching the same line number in an earlier file.
- The preview icon in the whole-file window did nothing; it now toggles that window's preview.
- The dark band between each pane's header bar and its content is gone; a pane's gap now sits around the pane, not between its own rows.
- The search box no longer selects the first letter typed into it, which silently ate a character when typing quickly.
- An added file no longer reports a line removed that never existed.
- Fixed a NativeAOT crash when previewing an image: size formatting used an F# printf specifier that cannot be compiled ahead of time. The crash report can now be copied out of the error dialog.
- The commit list column headed `COMMIT` showed the message's first line while a details row headed `Commit` showed the hash; they are now `SUBJECT`, `Hash` and `Message`.

## Under the hood

- FSharp.Core now comes from the SDK instead of being pinned to version 10.
- Pure presentation logic — sizes, image fit and zoom, row collapse thresholds, change-block scaling, colour blending — moved from the C# views into `GitKay.Core.Presentation`, and preview formats and zoom gestures are typed rather than strings and ints.
- The `/dev/null` sentinel for a missing file side is spelled once, in `FileChange`, instead of in 46 places.
